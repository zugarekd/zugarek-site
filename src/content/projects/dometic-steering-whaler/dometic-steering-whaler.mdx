## Overview

This project documents the bench setup and commissioning process for a **Boston Whaler 130 Super Sport** equipped with:

- **Simrad GO7**
- **Dometic Optimus EPS steering**
- **EA1000 autopilot module**
- **Precision-9 heading sensor**
- Full **NMEA 2000 backbone**

The goal was to create a stable, predictable network environment before launching — including simulating engine RPM and water speed to validate autopilot and steering behavior.

---

## Goal

Establish a **stable speed and RPM source** on the NMEA 2000 network so that:

- The autopilot behaves correctly
- The helm display shows consistent data
- Steering calibration can be completed
- Limp-mode or fault conditions caused by missing data are eliminated

---

## Network Architecture

This installation runs four separate CAN-based networks:

- **NMEA 2000 backbone** — shared bus carrying Simrad GO7, Simrad autopilot computer, Precision-9 compass, and the Mercury VesselView gateway
- **Dometic CAN 1** — dedicated network between the helm and the EPS steering system; fairly isolated and not bridged to the NMEA 2000 backbone
- **Dometic CAN 2** — the EA1000 autopilot module connects to the NMEA 2000 backbone here, consuming heading, speed, and RPM data to drive the EPS electric actuator
- **Dometic CAN 3 (steering network)** — internal bus between the EA1000 and the EPS electric actuator; this is also tied back into the NMEA 2000 backbone to close the loop between the steering system and the chartplotter

The NMEA 2000 backbone was built with:

- Proper termination (120Ω at both ends)
- Dedicated power tee
- Individual drop cables per device
- Verified backbone voltage and resistance

Treat backbone power and termination as **Layer 1** — if this isn’t correct, nothing else will behave predictably.

## ED1800 — Dometic Optimus EPS Display

The **ED1800** is the primary helm display for the Optimus EPS system. It provides:

- Steering configuration
- Rudder limit setup
- System diagnostics
- Autopilot integration status
- Real-time network data

### Accessing Dealer Settings

> **Critical:** Without the dealer code you cannot complete steering stop calibration, rudder limit setup, or autopilot commissioning. This is the single most important step — the system cannot be properly configured through the standard user menu alone.

To enter advanced configuration:

1. Hold the **Menu** button for ~3 seconds
2. Enter dealer code: **`0906`**

## Simrad Autopilot Computer

The **Simrad autopilot computer** (AP unit) bridges the Simrad GO7 to the NMEA 2000 backbone. This is required for the autopilot to function — the GO7 alone does not drive the steering; it sends commands through the autopilot computer, which translates them into NMEA 2000 messages consumed by the EA1000 on the Dometic CAN 2 bus.

Without this unit on the network, the EA1000 has no source of autopilot commands and the heading hold / nav steer modes are unavailable.

---

## Mercury VesselView Bridge

The **Mercury VesselView gateway** connects the Mercury engine's proprietary CAN bus to the NMEA 2000 backbone. This allows the engine to publish:

- RPM (PGN 127488)
- Engine hours
- Coolant temp and other engine diagnostics

This was the production source of RPM data on the water, replacing the ESP32 simulator used during bench testing. With the VesselView gateway on the network, the EA1000 receives real engine RPM which is required for correct autopilot idle detection and speed-based steering gain.

---

## EA1000 Autopilot Integration

The **EA1000** integrates directly with the Optimus EPS and the NMEA 2000 backbone via its CAN 2 port.

> **Gotcha:** The Dometic CAN 2 network is self-powered — it draws power internally from the EA1000/EPS system and does not require a dedicated power drop on that segment. Adding one is unnecessary and could cause issues. Only the main NMEA 2000 backbone needs its own power tee.

Once configured, it consumes:

- Heading data (Precision-9)
- Speed input
- Engine RPM (from VesselView gateway)
- Rudder feedback
- Autopilot commands (from Simrad autopilot computer)

![EA1000 Module](/projects/dometic-steering-whaler/PXL_20260218_020020217.jpg)

## Precision-9 Compass Placement

The **Precision-9** heading sensor was mounted **under the seat** rather than at the helm. The helm area contains significant magnetic interference sources: the helm controls, wiring runs, and mounting hardware all create a magnetic environment that will cause the compass to report incorrect headings.

Mounting under the seat moves the sensor far enough from the helm electronics to get a clean, stable heading signal. The Precision-9 connects to the NMEA 2000 backbone via its own drop cable from that location.

## What It Simulates

The ESP32 broadcasts:

- **PGN 127488** — Engine Rapid Update (RPM)
- **PGN 128259** — Speed Through Water (STW/SOW)
- Heading and other optional test data

This allows:

- Steering stop calibration
- Autopilot idle detection validation
- RPM display verification
- Network troubleshooting without the engine running

## EA1000 Autopilot Module Fitment

Installing the Dometic **EA1000** on a Boston Whaler 130 Super Sport required a few mechanical adjustments.

The actuator length was wider than the factory steering cylinder spacing. This required shimming to properly center and align the linkage. SeaStar does offer a smaller-engine kit designed for tighter installations, but in this case proper shimming resolved the geometry and ensured smooth travel.

![Steering Cylinder Shim](/projects/dometic-steering-whaler/ea1000_shim.jpg)

The steering arm bracket also required minor grinding as it was hitting the actuator.

![Steering Arm Bracket Modification](/projects/dometic-steering-whaler/ea1000_grind.jpg)

During initial fitment and testing, the wire loom was temporarily secured to allow adjustment before final routing and strain relief.

![Temporary Wire Loom Routing](/projects/dometic-steering-whaler/ea1000_wiring.jpg)

After shimming and clearancing, the system cycled smoothly through full travel and trim.

## Helm Mounting Bracket Fabrication

The supplied helm mounting plate did not fully cover the holes from the previous steering system installation. The exposed holes looked unfinished and would have required cosmetic filler.

Instead, a new **stainless steel backing plate** was fabricated slightly larger than the original bracket so it completely covers the previous mounting pattern. This provides a cleaner appearance while maintaining a solid mounting surface for the new helm.

![Custom Helm Mounting Bracket](/projects/dometic-steering-whaler/helm_bracket.jpg)

With the new bracket installed, the helm, steering wheel, and display were mounted and aligned. This completed the primary helm layout for the steering system installation.

![Helm, Wheel, and Display Installed](/projects/dometic-steering-whaler/helm_installed.jpg)
